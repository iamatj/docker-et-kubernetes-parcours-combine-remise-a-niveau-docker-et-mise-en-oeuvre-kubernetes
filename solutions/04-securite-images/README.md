# Correction du TP 04 – Scanner et durcir ses images

**1.** Les chiffres changent chaque semaine (nouvelles CVE, nouvelles versions des images de base) ; l'ordre de grandeur est constant : plusieurs centaines de vulnérabilités HIGH et CRITICAL pour `cordee-api:avant`, quelques-unes (souvent moins de dix) pour `cordee-api:1.0`. Elles viennent presque toutes des **paquets du système** de l'image `python:3.13` complète : compilateurs, bibliothèques de développement, outils d'images (ImageMagick), clients de bases de données… dont l'API n'a aucun besoin. La partie Python (Flask, gunicorn, psycopg) est la même dans les deux images.

**2.** `affected` sans version corrigée : il n'existe pas encore de correctif dans la distribution. On vérifie d'abord si le paquet est réellement utilisé par l'application (souvent non, il est seulement présent), on peut l'ignorer explicitement et temporairement (fichier `.trivyignore` avec une justification et une date de revue), changer d'image de base (une image plus minimale, distroless) ou suivre la CVE jusqu'à la publication du correctif. Dans tous les cas : reconstruire régulièrement les images, même sans changement de code, pour récupérer les correctifs.

**3.** En lecture seule, nginx ne peut plus écrire son fichier PID ni ses fichiers temporaires ; dans l'image `nginx-unprivileged`, ils sont configurés dans `/tmp`, d'où le tmpfs. `--cap-drop ALL` retire toutes les capacités Linux (une partie des pouvoirs de root découpée en morceaux : changer de propriétaire, ouvrir un port inférieur à 1024, contourner les permissions de fichiers…). Même si un attaquant devenait root dans le conteneur, il ne pourrait pas s'en servir. `no-new-privileges` empêche de regagner des droits par un programme `setuid`. On retrouvera exactement ces réglages dans le `securityContext` de Kubernetes (TP 10).

**4.** (1) Plusieurs hôtes : Compose pilote un seul daemon ; si le serveur tombe, tout tombe. (2) La reprise automatique : personne ne relance les conteneurs ailleurs, ni ne surveille qu'il y en ait toujours le bon nombre. (3) Les mises à jour sans coupure : `docker compose up` remplace les conteneurs, sans bascule progressive ni retour arrière automatique. On peut ajouter : la répartition de charge entre hôtes, la gestion des secrets, les droits d'accès par équipe.

**5.** Swarm est intégré à Docker et simple, mais son écosystème est resté petit et il n'évolue presque plus. Kubernetes est le standard de la CNCF : proposé par tous les clouds (EKS, AKS, GKE), avec un écosystème immense (Helm, Ingress, Gateway API, opérateurs, supervision). Cordée vise un cluster loué chez un hébergeur, et des compétences qui se recrutent : Kubernetes.

**Bonus.** Le scanner de secrets ne trouve rien dans l'API (aucun secret dans le code). `trivy config` signale sur `Dockerfile.avant` l'absence de `USER` (exécution en root) et l'absence de `HEALTHCHECK`, et éventuellement l'image sans tag précis.
