▼ un volume se branche sur un chemin

volume donnees-db

/var/lib/docker/volumes/…/_data · survit au conteneur

docker run -d --name pg \
  -v donnees-db:/var/lib/postgresql/data \
  postgres:17-alpine

  • stop / start : rien n'est perdu
  • rm sans volume : tout est perdu
  • volume anonyme (64 caractères hexa) : pas perdu, mais orphelin
  • détruisent un volume : docker volume rm, volume prune -a, compose down -v, rm -v

# sauvegarder un volume
docker run --rm -v donnees-db:/d:ro \
  -v ~/sauvegardes:/s busybox \
  tar czf /s/donnees-db.tgz -C /d .

Partir de l'incident : où étaient les 312 rendez-vous ? Dans la couche en écriture du conteneur db, ou dans un volume anonyme que personne n'a retrouvé. Question : quelle différence entre docker stop et docker rm pour les données ? Un volume n'est pas une sauvegarde : il survit au conteneur, pas à la panne du disque ni à un down -v.
