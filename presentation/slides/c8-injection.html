Le concept

Trois façons de donner la configuration à un pod

ConfigMap huiteo-configDB_HOSTDB_NAMEMESSAGE_ACCUEIL
Secret huiteo-dbDB_USERDB_PASSWORD

1env

Une clé à la fois, sous le nom que vous choisissez. Chez Huiteo : PostgreSQL attend POSTGRES_*.

env:
- name: POSTGRES_DB
  valueFrom:
    configMapKeyRef:
      name: huiteo-config
      key: DB_NAME
- name: POSTGRES_PASSWORD
  valueFrom:
    secretKeyRef:
      name: huiteo-db
      key: DB_PASSWORD

Dans le conteneur

$ env | grep POSTGRES
POSTGRES_DB=huiteo
POSTGRES_PASSWORD=Neige-2026

Si la ConfigMap changerien, tant que le pod tourne : rollout restart

2envFrom

Toutes les clés d'un coup, en gardant leur nom. Chez Huiteo : l'API, qui lit DB_* et MESSAGE_ACCUEIL.

envFrom:
- configMapRef:
    name: huiteo-config
- secretRef:
    name: huiteo-db

Dans le conteneur

$ env | grep -E 'DB_|MESSAGE'
DB_HOST=postgres
DB_NAME=huiteo
MESSAGE_ACCUEIL=Rendez-vous de déc…
DB_USER=huiteo
DB_PASSWORD=Neige-2026

Si la ConfigMap changerien non plus : les variables sont lues au démarrage (TP 08, question 3)

3volumeMounts

Un fichier par clé, dans un dossier. Pour de vrais fichiers de configuration : nginx.conf, certificats.

volumes:
- name: config
  configMap:
    name: huiteo-config
containers:
- volumeMounts:
  - name: config
    mountPath: /etc/huiteo
    readOnly: true

Dans le conteneur

$ ls /etc/huiteo
DB_HOST  DB_NAME  MESSAGE_ACCUEIL
$ cat /etc/huiteo/DB_HOST
postgres

Si la ConfigMap changele fichier suit, en une minute environ (pas avec subPath). À l'appli de le relire.
